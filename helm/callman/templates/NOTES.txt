1. Migrations run as a one-shot Job each revision. Until it completes, app
   pods may CrashLoopBackOff briefly — that is the migration gate, not an
   error. Watch it with:

     kubectl -n {{ .Release.Namespace }} logs -f job/{{ include "callman.fullname" . }}-migrate-{{ .Release.Revision }}

2. Reach the services:
{{- if .Values.backend.route.enabled }}
     Backend:  https://{{ .Values.backend.route.host | default "<route host>" }}
{{- else if .Values.backend.ingress.enabled }}
     Backend:  https://{{ .Values.backend.ingress.host }}
{{- else }}
     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "callman.fullname" . }}-backend {{ .Values.backend.port }}:{{ .Values.backend.port }}
{{- end }}
{{- if .Values.admin.route.enabled }}
     Admin:    https://{{ .Values.admin.route.host | default "<route host>" }}
{{- else if .Values.admin.ingress.enabled }}
     Admin:    https://{{ .Values.admin.ingress.host }}
{{- else }}
     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "callman.fullname" . }}-admin 5100:5100
{{- end }}

3. First login: the ADMIN_BOOTSTRAP_EMAIL / ADMIN_BOOTSTRAP_PASSWORD account
   is seeded only while the admin_users collection is empty. Log in and
   change the password immediately.

4. License: the platform runs READ-ONLY until a license certificate is pasted
   in the admin panel (On-Prem -> License).

5. Verify the installation:

     helm test {{ .Release.Name }} -n {{ .Release.Namespace }}

Docs: docs/HELM-INSTALL.md in the callman-onprem repository.
